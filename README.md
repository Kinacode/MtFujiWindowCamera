# 富士窓カメラ / MtFujiWindowCamera

最新版APKは [Releases](https://github.com/Kinacode/MtFujiWindowCamera/releases/latest) のAssetsにある `app-debug.apk` からダウンロードできます。Android 10以上に対応します。


Android 10以上の端末用。CameraXで撮影し、端末内のMI-GANで固定マスクの局所補完、OpenCVで住宅ぼかしを行います。ネットワーク・位置情報・ストレージ読取権限は要求しません。

## インストールと使い方

1. `app-debug.apk`をAndroid端末へ転送して開き、転送に使ったアプリの「不明なアプリのインストール」を許可してインストールします。
2. カメラを許可し、縦向きで窓から撮影します。同じ背面カメラ、同じ撮影位置で使用してください。
3. 「写真」から既存写真も読み込めます。標準の「この窓」モードは範囲指定不要です。提供見本と同じ窓・ズーム・縦3:4の画角で使います。
4. 「編集」→「AI加工」。山と重なる設備も推定補完する場合は「山の重なりを補完（推定）」をONにします。OFFでは山保護範囲を補完しません。
5. 「比較」で元写真と確認して「保存」。元写真も別に保存する設定は「•••」から選べます。処理失敗時も元画像は保持します。
6. 「日記」→「＋ 過去の写真を登録」で既存の写真を複数選択して直接登録できます。加工は不要です。「日記」で撮影日と写真・メモを見返せます。EXIF撮影日を取得できた場合はアプリ内部にだけ保持し、公開JPEGへ元EXIFを引き継ぎません。
7. 従来の手動範囲設定は詳細メニューから使えます。画角の一致確認と加工後プレビューは必要です。

加工結果は `Pictures/FujiWindowCamera/Processed`、元画像の書き出しは `Pictures/FujiWindowCamera/Original` に保存されます。どちらもGPS・元EXIFを引き継がないJPEGです。撮影機器の生JPEGを公開フォルダへコピーしません。

## 手動モードの画像処理と制約（標準AIモードは下記参照）

- 赤マスクに対してOpenCV Telea inpaint（半径3px）。赤以外にインペイント結果は適用しません。電柱など太い範囲や複雑な背景は不自然になることがあるためプレビューで確認してください。
- 黄マスクだけGaussian Blur（61px、sigma=16）。境界の外は変更しません。住宅全体を覆うよう範囲を登録してください。自動検出・自動匿名化はありません。
- 保護範囲を8px拡張し、赤／黄と重なる場合は処理全体を中止します。稜線に重なった電線は除去できません。保護範囲未登録でも中止します。
- 生成AI・山頂補完・空の置換・色調補正・彩度／コントラスト／色温度の調整はありません。位置補正も行わず、手動で固定ガイドに合わせます。
- 処理前のデコード済みARGB画素を保持し、赤／黄の和集合にだけ加工画素を合成します。**JPEG保存では非可逆圧縮が発生するため、保存後のマスク外画素の完全一致は保証できません**（品質98）。
- CameraXには1600×1200を要求します。機種によって近い解像度が選ばれます。メモリ保護のため読込時に長辺2000px以下になるよう整数サンプリングします。元画像の書き出しも、この未加工・向き補正済みの作業画像からの再圧縮です。センサーRAWや撮影JPEGの完全コピーではありません。
- アプリ内の処理は別Bitmapに対して実行します。撮影JPEGは一時キャッシュに保持し、加工・保存で上書きしません。再撮影とアプリの再起動では一時撮影を破棄するので、必要な画像は先に保存してください。端末のメモリ不足によるプロセス終了を含む、未保存状態の復元はありません。
- 保存はMediaStoreのIS_PENDINGを使い、書込失敗したファイルは削除します。元／加工は独立した保存なので、加工保存が失敗しても元画像が先に保存されている場合があります。再試行は別ファイルを作成します。
- ガイド写真と固定範囲はアプリ専用領域に置き、Androidバックアップは無効です。アンインストールで削除されます。
- 実際の窓の写真を用いたマスク調整と、実機カメラ・自然な仕上がりの確認は利用者の端末で必要です。

## ビルド

JDK 17、Android SDK Platform 35 / Build Tools 35.0.0が必要です。

```sh
# local.propertiesへ自分のSDKパスを設定（またはANDROID_HOME）
./gradlew assembleDebug
./gradlew lintDebug assembleDebugAndroidTest
# エミュレーターまたは接続端末で画像処理・EXIFテスト
./gradlew connectedDebugAndroidTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

APK: `app/build/outputs/apk/debug/app-debug.apk`

`.github/workflows/android.yml` はpush / pull_request / 手動実行に対応。成功したActionsのArtifactsから`FujiWindowCamera-debug`をダウンロードするとAPKを取得できます。画像処理の計装テストをエミュレーターでも実行します。CIごとにdebug署名鍵が変わり得るため、別ビルドで署名不一致になったら旧アプリのアンインストールが必要です（保存済みの写真は残り、範囲とガイドは消えます）。公開配布用のrelease署名鍵は含みません。

## バージョン1.1：写真読み込み・富士日記

- 「写真を読み込む」でAndroidのファイル選択画面から写真を選択します。JPEG・PNGなど端末がデコードできる静止画に対応します。80MB以下、作業画像の長辺は従来どおり2000px以下です。元ファイルは変更しません。キャンセル・読込失敗では現在の作業画像を保持します。
- 読み込み時は今回の範囲をリセットします。同じ縦横比でもトリミング・レンズが違う可能性があるため、範囲設定と富士山の保護範囲を登録し直してください。
- カメラの許可をしなくても、写真読み込み・加工・富士日記を使えます。
- 「富士日記」はアプリが保存した元画像・加工後画像を、**保存日順**に一覧表示します。「すべて／加工後／元画像」で絞り込み、タップで拡大プレビューできます。v1.1では保存日、v1.2では下記のEXIF撮影日時を使用します。
- 日記には「保存」または「その他（•••）→ 元画像だけ保存」で保存した写真が表示されます。未保存の撮影・読込画像は表示されません。旧版が保存した写真も同じアプリの更新インストールなら表示対象です。
- 日記はMediaStore内の写真を直接参照するため、ギャラリーで削除すると一覧からも消えます。端末内の全写真を列挙する権限は要求しません。アプリをアンインストール後に再インストールした場合など、所有権が変わった写真は一覧に出ないことがあります。
- v1.0と同じdebug署名でビルドしているため、この作業領域で生成した旧APKからは通常そのまま更新できます。


## バージョン1.2：EXIF撮影日時

- 元の撮影JPEG・読み込んだ写真の `DateTimeOriginal` をEXIF削除前に取得し、富士日記を撮影日時の新しい順で表示します。元画像・加工画像には同じ撮影日時を対応付けます。
- `OffsetTimeOriginal` が有効なら並び順に時差を反映します。表示は元写真の現地日時を保持します。時差がない／不正な場合は保存時の端末タイムゾーンを使用します。
- `DateTimeOriginal` がなければ `DateTimeDigitized` を使い、「EXIFデジタル化日時」と明示します。一般の `DateTime` は更新日時の可能性があるため撮影日としては扱いません。不正な日時も採用しません。
- EXIFの撮影日時がない場合、アプリのカメラ撮影は「撮影日時（アプリ記録）」、読み込んだ写真は「保存日時（撮影日時なし）」を表示します。
- 撮影日時はアプリ専用領域に記録し、公開JPEGのEXIFは引き続き削除します。GPS・機種情報などの記録は行いません。アプリのデータ消去やアンインストールで日記の撮影日時データは消えます。
- **v1.0／v1.1で保存済みのJPEGは、EXIFを削除済みなので撮影日時を復元できません。** それらは保存日時と明示して表示します。元のEXIF付き写真をv1.2で読み込み直して保存すると、EXIF撮影日時を日記に反映できます。


## v1.3：縦画面・日記帳のUI

- スマートフォンの縦持ちを基本に、下部の「撮る／編集／富士日記」で切り替えます。横方向にスクロールする操作ボタンは廃止しました。
- 紙色・深緑・セリフ体の見出しを使い、写真が中心になる画面へ変更しました。撮影画面ではシャッターと写真読み込み、編集画面では範囲設定・比較・加工・保存を表示します。
- 富士日記は全画面の写真カードになりました。「日記」では元写真と加工後を同じ撮影の記録にまとめ、「加工後／元写真」で個別に見ることもできます。
- 「日記を書く」で最大2000文字のひと言メモを保存・編集できます。メモはアプリ専用領域に保存され、共有JPEGには含めません。アンインストール／データ消去では消えます。
- 「•••」から元写真だけの保存と撮り直しを選べます。
- 縦向きの撮影では画角が変わるため、従来の横向きマスクは初回に登録し直してください。
- AIによる電線・住宅の自動検出は、このバージョンには搭載していません。富士山の稜線を誤検出するリスクを評価するため、検出モデルの選定と実際の窓の写真での検証が必要です。将来追加する場合も、生成AIによる写真全体の再生成ではなく、検出候補を確認して局所処理する方式が前提です。

検証用の画面画像はReleasesのPNG添付で確認できます。日記と編集の画面に写る画像は、自動UIテストのための描画したテスト画像であり、実際の富士山写真ではありません。


## v1.4：この窓専用・範囲指定なし

提供された縦3:4の3枚の見本を目視で読み取り、電線の曲線・鉄塔上部・住宅の位置と富士山の保護領域を座標化しました。見本写真そのもの・EXIF・GPSはアプリ／リポジトリに同梱していません。

1. 見本と同じ窓・レンズ・ズーム・縦3:4の画角で撮影するか、写真を読み込みます。撮影画面の破線が3本の電線の目安です。ピンチでズームでき、ズーム倍率は端末内に保持します。
2. 「見本と同じ窓・縦3:4の画角です」を確認してチェックし、「加工する」。範囲を描く操作は不要です。
3. 加工前後を比較して保存します。「この窓プリセット」から従来の手動モードに戻すこともできます。

- 3本の電線の固定曲線付近で、暗い細線の両側に背景があることを確認して位置を補正します。全体の上下移動は±3%、傾き補正は−1〜2%、線の局所探索は±0.5%の範囲です。各電線のサンプルの65%以上が一致しない場合は処理を停止します。
- 上部3本に加え、決めた空の領域にある長い細線、鉄塔上部の細部を候補にします。線の候補以外の画素をインペイント結果で上書きしません。
- 除去は画像高さ76%より上に限定し、さらに固定の富士山保護領域と8pxの余白を除外します。補正前／補正後の保護領域の和集合を使い、電線の補正に引きずられて保護が外れないようにしています。
- **富士山に重なる鉄塔・電線と稜線付近は残ります。完全除去ではありません。** 山頂・稜線の再生成や補完は行いません。
- 住宅は左下・中央下・右端の固定多角形でぼかします。保護領域との重なりを除外し、境界は範囲内だけでぼかしを弱めてなじませます。稜線に近い住宅や、範囲外の建物はぼかされない場合があります。木や道路の自動分類は行っていません。
- 一般的なAI物体検出ではなく、この窓に限定した固定マスク＋軽い位置補正です。違う窓、別のトリミング、大きな構図ずれには対応しません。電線が合うことだけで富士山の位置を保証できるわけではないため、同じ画角の確認と処理後プレビューは必要です。
- 固定領域外と保護領域のデコード済み画素は維持し、JPEG保存時の非可逆圧縮のみ発生します。

v1.3当時の座標はチャットに表示された写真から作成しており、この時点では元の添付ファイルを直接読み込んだ画素単位の実写検証は行えていません。固定窓テストでは位置をずらした線の描画画像を使い、位置補正・元Bitmapと保護領域／マスク外の画素保持・電線不在／違う縦横比での処理停止を検証します。


## v1.5：山に重なる設備の局所補完・ブラックUI

ユーザーの追加要望により、従来の「山に重なる設備は残す」制限を、補完ON時だけ緩めました。最新の要望を優先しており、過去の保護優先モードとは動作が異なります。

- 黒基調・白い丸形シャッター・ズーム倍率・アルバム読込ボタン・短いモードラベルのカメラUIへ変更。富士日記も黒基調です。
- 編集画面の「山の重なりを補完（推定）」は初期状態でON。OFFにするとv1.4の山保護モードに戻ります。
- ON時は鉄塔全体・中央の支柱／横梁・右側の電線などの固定領域内で、細い明暗構造を抽出して局所インペイントします。元写真の隠れた山肌を回収するものではなく、周辺画素からの推定です。稜線や雪の模様が実際と異なる場合があるので、比較してから保存してください。未遮蔽の山頂は補完対象から除外します。
- 写真全体の生成AI再描画は行いません。参考に提示されたAI加工画像は仕上がりの参考として扱い、元写真への貼り付け・色調移植・彩度や夕焼けの強調には使いません。参考画像と同等の生成品質を保証するものではありません。
- マスク外と元Bitmapは保持します。推定補完のON/OFFを変更すると加工結果を無効にし、再処理が必要です。元写真の別保存は「•••」メニューで設定できます。
- 局所補完を使った加工写真は日記に「局所補完あり」と表示します。この記録はアプリ専用領域にのみ保持し、JPEGにはメモ・補完記録・元EXIFを付けません。
- 実写添付ファイルでの処理品質確認は未実施です。テストでは山の前に支柱を描いた画像を使い、ONでだけ山上の支柱が補間されること、範囲外・元画像・未遮蔽山頂の画素保持を検証します。


## v1.6：端末内の本物のAIインペイント

標準の「この窓」モードは、**MI-GAN-512-Places2（公式ONNXパイプライン）＋ ONNX Runtime Android 1.31.1** に切り替えました。従来のOpenCV TeleaをAIと呼び替えたものではありません。

- 公式の約27MBの学習済みモデルをビルド時にSHA-256検証してAPKへ収録します。初回加工時に端末内へ展開し、CPUで推論します。APIキー・外部サーバーは不要です。
- 依存ライブラリのINTERNET／ACCESS_NETWORK_STATE権限はManifestで除去し、ランタイムのテレメトリも無効化しています。写真を端末外に送信しません。
- 電線位置はこの窓の固定設定と線検出で決め、穴埋めをニューラルネットで実行します。上部3本のマスクは低コントラスト部分でも連続させ、周囲まで広げます。右側の斜め線・曲線は固定の探索帯内で短い線分も拾うようにしました。
- 最大512pxの重なり付き領域ごと（v1.6.1以降）にモデルへ渡し、推論結果を重み付きで合成します。長い電線を写真全体と一緒に512pxへ縮めて処理することを避けます。マスク外は元のデコード済み画素を使い、住宅だけGaussian Blurを適用します。
- 「AI加工」ボタンで開始し、進捗を表示します。「処理を中止」で途中画像を破棄して元写真へ戻れます。AIに失敗した場合にOpenCVへ黙って切り替えることはありません。
- 「山の重なりを補完（推定）」がONなら固定設備領域の山肌・輪郭もAIで推定します。OFFなら山保護領域を除外します。元の山肌の正確な復元、全電線の完全除去、参考の大規模生成AIと同等の仕上がりは保証できません。比較してから保存してください。
- 日記では新しいAI処理の写真を「AI加工」と表示します。過去のOpenCV補完の記録をAI処理とは表示しません。
- 手動で範囲を指定する従来モードはOpenCV処理のままで、「手動加工」と区別します。
- JPEG保存の再圧縮と最大2000px以下の作業解像度は従来どおりです。処理時間は端末と写真の大きさによって変わります。端末のメモリ不足時は停止し、元画像は保持します。

モデル出典・固定リビジョン・ハッシュとMITライセンスはthird_partyおよびAPK内assets/licensesに含めています。提供された実写真そのものは公開ソースに入れていません。Androidテストでは実際のモデルを使った線の除去・マスク外と元画像の保持・中止動作を確認します。

## v1.6.1：報告された電線・支柱の残りを修正

- 電線3本の上下補正を±6.4%、局所探索を±0.9%へ拡張。一致条件は各線65%以上を維持します。大きな構図ずれや電線不在時は停止します。
- 左下の空だけ低コントラストの細線を追加探索し、右端の横金具を追加除去。ケーブルは明暗両方の細線を確認するので、夕日に反射した線にも対応します。中央支柱の左側へ固定補完領域を広げました。
- 512pxタイルにして大きく縮小されることを抑えます。重なり部分は重み付き合成し、マスク外を元画素で保持します。除去面積が22%を超えた場合は停止します。
- 提供ZIPのJPEG（576×768）を非公開のローカル検証に使用。実モデルで推論し、電線3本は80/80点ずつ一致、補正+4.6%、傾き+0.5%でした。範囲外の画素一致を確認しました。細線の残留や補完痕はまだあり、完全除去の品質保証ではありません。
- 実写真・EXIF・私有の検証出力はGitにもリリースにも含めません。

## v1.6.2：過去画像を富士日記へ直接登録

「日記」の「＋ 過去の写真を登録」でAndroidのファイル選択画面から画像を複数選べます。加工・保存ボタンを経由せず、登録完了後に日記へ並びます。編集中の写真は置き換えません。

- EXIF DateTimeOriginalとOffsetTimeOriginalを優先して撮影日時を取得し、撮影日時順に表示します。ファイルの更新日を撮影日として使いません。デジタル化日時しかない場合は「EXIFデジタル化日時」と区別します。
- EXIFの有効な日時がない場合は「撮影日不明」。並べ替え用の保存日時は、撮影日時ではないことを明示します。
- 元ファイルを変更せず、向き補正したJPEGコピーをOriginalフォルダに保存します。従来と同じ最大2000px以下の作業解像度・品質98で再圧縮し、GPS・元EXIFは公開コピーへ引き継ぎません。撮影日時だけアプリ内部に保持します。
- 同じ元ファイルの再選択はSHA-256で判定し、重複登録を避けます。登録済みコピーを削除した場合は再登録できます。読み込めない画像が混ざっていても残りは登録し、登録・重複・日付なし・失敗の件数を表示します。
- Androidテストで実JPEGのEXIF読取、更新日時より撮影日時の優先、元ファイルの保持、公開コピーのEXIF除去、重複防止、日付なし、複数登録の継続と撮影日順を検証します。
